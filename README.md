# FixDesk：4 周，从 0 到能上线（Java 后端实战方案）

> 给"有 Java 语法基础、缺真实项目经验"的人准备的一条最短路径。
> 原则只有一条：**不是学完再做，而是在做的过程中学，并且每一步都留下真实工作会留下的痕迹。**

---

## 一、先给结论：你做什么

**IT 报修工单系统（FixDesk）**

员工提报修单 → 管理员派单 → 技术员接单处理 → 员工评价关闭；管理员看统计、导出 Excel；超时工单自动提醒。

为什么选它（不是拍脑袋）：

| 理由 | 说明 |
|---|---|
| 闭环短 | 3 个角色 + 1 个状态机 + 13 个接口，30 小时能做完，不会烂尾 |
| 技术点密度高 | 登录鉴权、分页多条件查询、事务、状态流转、数据权限、Excel 导出、定时任务、日志排查——初级 Java 岗 JD 上的词基本全覆盖 |
| 面试可信 | 有并发点（两人抢单）、有权限边界（越权）、有线上坑（时区、OOM、慢查询），比编一个"电商秒杀"更经得起追问 |
| 业务好懂 | 不需要懂财务/电商/支付规则，省下的时间全花在技术上 |

**明确不做**：前端（用 Swagger/Apifox 调接口）、微服务、支付、工作流引擎（Activiti/Flowable）、完整 RBAC、Redis 缓存、消息队列。
理由：这些是"简历词"，不是"能力词"，4 周内做只会每个都半成品。详细取舍见 [01 文档](./docs/01-需求与技术方案.md)。

## 二、你的现状 → 这个方案补什么

| 你有的 | 你缺的 | 方案里怎么补 |
|---|---|---|
| 对日开发的式样书、单体测试习惯 | 从 0 设计表、设计接口 | 第 1 周强制先出需求评审 + 表设计 + 接口契约，评审通过才写码 |
| 低代码平台拖拽经验 | 手写 Spring Boot 分层 | 每天一个接口，按 controller/service/mapper 分层手写，禁止整段复制 |
| Java 语法 | 框架、ORM、事务、并发 | 每天任务卡固定"今天必须搞懂的 2 个点"，带"为什么" |
| 没和人协作过代码 | Git 分支 / PR / Code Review | 单人也走 Issue → 分支 → PR → 自查 → 合并，全程留痕 |
| 没上过线 | 部署、回滚、线上排查 | 第 4 周真的打 jar、跑起来、造 2 个故障再修掉 |

一句话：**你的严谨是优势，不要丢；你缺的是"从需求走到线上"的全链路手感。**

## 三、4 周节奏（每周约 10 小时）

| 周 | 主题 | 关键产出 | 周末验收 | 版本 |
|---|---|---|---|---|
| W1 | 打通链路 | 需求评审记录、ER 图、接口清单、能登录能提单 | 3 个角色登录 + 提单 + 列表 + 详情 | v0.1.0 |
| W2 | 主流程闭环 | 状态机、派单/接单/完工/评价、数据权限、单测 | 一条单走完全流程，两人抢单只有一人成功 | v0.5.0 |
| W3 | 真实业务里的脏活 | 导出、统计、定时任务、日志、2 次故障演练 | 10 万数据下不慢、导出不 OOM、能靠 traceId 定位 | v0.9.0 |
| W4 | 上线与表达 | 部署脚本、上线单、复盘、3 分钟 demo | 能上线、能回滚、能讲清 | v1.0.0 |

**每晚 1.5 小时的时间盒**（重要，不然天天熬夜）：

```
20 min  只看今天要用的那部分（官方文档 / 报错原文），不看长视频
60 min  写代码，卡住 40 分钟就跳过，记进 blockers.md
10 min  git commit + 写 5 行日报 + 明天第一件事
```

周末各留 2~3 小时做"整周串起来"的活（联调、提测、复盘）。

## 四、完成标准（做到这几条才算真的做完）

- [ ] 3 个角色都能登录，看到的工单范围不同；越权访问返回 `40300` 而不是空列表
- [ ] 一条工单能走完 提单 → 派单 → 接单 → 完工 → 评价，非法跳变被拦截
- [ ] 两个技术员同时接同一单，只有 1 个成功，另一个收到 `40901`
- [ ] 列表分页 + 3 个筛选条件，10 万条数据下 `explain` 走索引
- [ ] 导出 1 万条 Excel 不 OOM，有优化前后的耗时对比
- [ ] 所有异常返回统一 JSON，带 `traceId`，能靠 traceId 在日志里还原一次请求
- [ ] Git 上有 ≥30 个有意义的 commit、≥8 个 PR、3 个 tag，Issue 全部关闭
- [ ] 3 分钟内讲清：做了什么、难在哪、怎么解决、有什么数据

## 五、Day 0：环境（你这台机器已实测）

| 项 | 现状 | 要做什么 |
|---|---|---|
| JDK | ✅ 17.0.17（`D:\JavaJDKS\17.0.17`） | 无需动，确认 `JAVA_HOME` 指向它 |
| Maven | ⚠️ 装的是 `4.0.0-rc-5` | **别用它跑 Spring Boot 3**（插件容易报错）。IDEA 里换自带 3.8.x，或下载 3.9.x 配到 `D:\JavaMaven` |
| MySQL | ✅ 8.0，服务 `MySQL80` 正在跑，3306 可连 | 记好 root 密码；建库 `fixdesk` |
| Git | ❌ 未安装 | `winget install --id Git.Git -e`，装完重开终端 |
| IDEA | ✅ 2022.3.3 | 能编译运行 Spring Boot 3；Spring 配置提示不全不影响，别为它折腾升级 |
| Docker | ❌ 未安装 | **不需要**，MySQL 已本地 |
| Maven 镜像 | ⚠️ 没有 `~/.m2/settings.xml` | 配阿里云镜像，否则下依赖能等到睡着（配置见 [03 文档](./docs/03-Git与协作流程.md) 第 5.1 节） |

装完 Git 后，在 `fixdesk` 目录执行一次初始化（脚本已备好，本机没有 `pwsh`，用系统自带的 `powershell`）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\day0-init.ps1
```

它只做三件事：`git init`、按规范提交现有文档、打印第一周该建的分支和 Issue。脚本不联网、不推远端、不改你的全局 Git 配置。
现在直接跑会停在第一步并提示你装 Git——这是预期行为，说明检查生效了。

## 七、开始之前的三句话

1. **每天都要提交代码**，哪怕 20 行。中断三天，这个项目就死了。
2. **卡住超过 40 分钟就跳过**，记进 `blockers.md`，第二天带着具体报错去查，比硬扛高效十倍。
3. **先走完整流程，再回头补完美**。烂尾的"完美设计"对面试价值为零，跑起来的"丑陋系统"能讲 40 分钟。
