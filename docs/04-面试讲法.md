## 3. 四个难点（每个都能撑 5 分钟）

### 难点一：并发抢单（面试出现率最高）

- **现象**：两个技术员同时点"接单"，都提示成功，日志表出现两条 ACCEPT。
- **分析**：`select` 出来状态都是 ASSIGNED，两个线程各自判断"状态合法"后都执行 `update`，后写的覆盖先写的。
- **方案**：把判断和修改压进一条 SQL——`UPDATE ... WHERE id = ? AND status = 'ASSIGNED'`，用**影响行数**判断是否抢到；为 0 就抛 409。这件事由数据库行锁保证，单机多机都成立。
- **结果**：20 并发压测，1 成功 19 失败。
- **追问预备**：
  - "为什么不用 `synchronized`？" → 单机有效，多实例无效；锁粒度大；数据库条件更新更简单。
  - "悲观锁 `select for update` 行不行？" → 行，但持锁时间长、容易死锁，这里没必要。
  - "`version` 乐观锁呢？" → 也可以，但状态本身就是最好的版本号，少一个字段。

### 难点二：数据权限（越权是新人最常犯的线上事故）

- **现象**：列表已经按角色过滤了，但直接改 URL 里的 ID 就能看到别人的单。
- **分析**：过滤写在列表查询里，明细接口没校验归属。
- **方案**：列表在 **SQL 层**加条件（不能在内存过滤，否则分页 total 全错）；所有按 ID 的操作统一走 `assertCanAccess`；越权返回 403。
- **结果**：20 条用例里 3 条越权场景全部拦截。
- **追问预备**：
  - "为什么不做成注解 + AOP？" → 现在只有 3 个角色、1 个资源，抽过头；扩展到多资源时会做成 `@RequireOwner` 注解。
  - "403 和 404 怎么选？" → 403 语义准确，404 防 ID 探测；项目内统一，我选 403 + 日志告警。

### 难点三：导出 OOM（体现"能上线"意识）

- **现象**：10 万条导出直接把服务打挂，堆内存溢出。
- **分析**：用了 `XSSFWorkbook`，全量数据先放内存再写文件；且用 `limit offset` 翻页，越往后越慢。
- **方案**：EasyExcel 流式写 + 每 1000 条一批 + `where id > lastId` 游标翻页。
- **结果**：1 万条从 OOM 变成 3 秒完成，峰值内存 < 200MB。
- **追问预备**：
  - "再大怎么办？" → 异步导出：落任务表，后台生成，前端轮询下载链接；或者走大数据平台。
  - "怎么定位的？" → `jmap -histo` 看对象占用、GC 日志看 Full GC 频率。

### 难点四：定时任务的时区坑（小而真实）

- **现象**：本地测好每天 2 点执行，部署后变成上午 10 点跑。
- **分析**：服务器/容器时区是 UTC，`cron` 按 JVM 默认时区解释，差 8 小时。
- **方案**：`@Scheduled(cron = "...", zone = "Asia/Shanghai")` 显式指定；JDBC URL 加 `serverTimezone`；`LocalDateTime` 别和 `Date` 混用。
- **追问预备**："多实例会重复执行吗？" → 会。解法是分布式锁（Redis `setnx`）或调度平台（XXL-Job）；本项目单机部署，代码里注释了扩展点。

## 4. 二十个高频追问（自查用，答不上就回去补）

| # | 问题 | 答案要点 |
|---|---|---|
| 1 | 为什么用 MyBatis-Plus 不用 JPA | 国内业务查询多、SQL 可控；单表 CRUD 省代码；复杂 SQL 直接写 XML |
| 2 | 分页插件原理 | 拦截 SQL 拼 `LIMIT`，另发一条 `count`；深分页慢的原因 |
| 3 | `@Transactional` 什么情况失效 | 同类内部调用、非 public、异常被 catch、类没被代理、多数据源未配事务管理器 |
| 4 | 事务里能不能调远程接口 | 不能，持锁时间长；用本地消息表/事务外调用 |
| 5 | ThreadLocal 为什么要 remove | 线程池复用导致用户信息串号 + 内存泄漏 |
| 6 | JWT 怎么注销 | 无状态注销不了；方案：短过期 + 刷新 token、黑名单（Redis）、版本号 |
| 7 | 拦截器和过滤器区别 | 过滤器在 Servlet 层、拦截器在 Spring MVC 层，能拿 HandlerMethod、能注入 Bean |
| 8 | 索引为什么没生效 | 函数/运算、隐式类型转换、前导 `%`、不符合最左前缀、区分度低 |
| 9 | `count(*)` 慢怎么办 | 走最小索引、加汇总表、缓存、近似值 |
| 10 | 怎么保证接口幂等 | 唯一索引、token 防重、状态机 CAS、去重表 |
| 11 | 统一异常怎么做的 | `@RestControllerAdvice` + 业务异常 + 兜底 `Exception`，错误码枚举 |
| 12 | 怎么排查线上 500 | traceId 找日志 → 看堆栈 → 看入参 → 复现 → 定位 |
| 13 | 日志级别怎么定 | error 需人工介入、warn 可自愈、info 关键业务动作、debug 本地 |
| 14 | 密码怎么存 | BCrypt 加盐哈希，不可逆；绝不 MD5 |
| 15 | 越权怎么防 | 每个资源操作校验归属；列表 SQL 层过滤 |
| 16 | 慢 SQL 怎么优化 | `explain` 看 type/rows/key → 加索引/改写法/减少回表/分页 |
| 17 | 定时任务重复执行 | 单机不会；多实例用分布式锁或调度平台 |
| 18 | 接口设计原则 | 资源化 URL、动词用 HTTP 方法、统一返回、版本兼容不删字段 |
| 19 | 如果 QPS 高 10 倍怎么办 | 先压测找瓶颈 → 索引/缓存 → 读写分离 → 水平扩容；说清当前是单机 |
| 20 | 这个项目有什么不足 | 单机、无缓存、无消息队列、权限模型简单、没有前端；说清"什么时候会加" |

**原则**：会的答细节，不会的答"我知道它解决什么问题，但我没实践过，我的理解是……"。**别编**，面试官一问细节就穿。

## 5. 对日经验怎么讲（这是你的差异化，不要藏）

不要说"我之前做的是外包，没什么技术含量"——这是自我否定。换成：

> 我前一段做对日开发，用的是低代码平台，技术栈上和 Java 后端不完全对口，但有两件事我延续下来了：
> 一是**写文档和式样书的习惯**，需求先落成文字再动手，返工少；
> 二是**单体测试的严谨**，每个分支都要有用例覆盖。
> 这次这个项目我就是按这个习惯做的：先出接口契约，再写代码，提测前列了 20 条用例。
> 技术栈上我确实是从零补的 Spring Boot，所以我把每个技术点都自己踩了一遍坑，比如并发抢单、导出 OOM。

这个回答同时做到了：不回避短板、把短板转成习惯优势、用项目证明学习能力。

## 6. 五句千万别说的话

1. "这个项目是跟着教程做的。" → 面试直接结束。
2. "我们用的是低代码，Java 我不太熟。" → 自我淘汰。
3. "并发问题用了 synchronized。" → 追问多实例就露馅。
4. "没有测试，功能能跑就行。" → 对日背景的人说这句，减分加倍。
5. "这个我没做过，不太清楚。"（然后沉默）→ 换成"我没做过，但我的思路是……"。
